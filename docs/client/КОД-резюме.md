# Резюме по коду (AZURE / KDFS)

Ветка: `feature/azure-qr-menu-and-dessert` → PR [#10](https://github.com/SumNic/kendala-foodservice/pull/10)  
Стек: Next.js 15 (App Router), ibronevik dropbox, vitest.

## Две фичи

| Фича | Суть |
|------|------|
| **Десерт в доставке** | Доп. позиция к полному обеду, **690 ₸**. Отдельного «только десерт» нет. |
| **QR-меню** | `/menu` — просмотр (афиша → фото дня). Заказа на этой странице нет. |

Поток обеда / корзины / уведомлений сохранён; правки точечные.

## Excel ↔ сайт

Колонки: `day`, `name`, `description`, `calories`, `type`.  
Контракт на день: `salad×2, soup×2, main×2, drink×2, dessert` (порядок проверяется парсером).  
Цена десерта — только `DESSERTS_PRICE` (690) в коде; текст в `description` на расчёт не влияет.  
«Голая» 9-я строка без `type=dessert` при загрузке отклоняется.

Парсер: `lib/menu-excel.ts`. Слоты/суммы: `lib/dessert.ts` (ланч 3690 только при 4 выбранных — как на main).  
Шаблон: `AZURE-menu-week-s-desertom-MOCK.xlsx`.

## QR-меню

| Что | Где |
|-----|-----|
| Страница | `app/menu/page.tsx` → `https://kdfs.kz/menu` |
| Deep-link | `?day=1`…`5` — сразу день, без афиши |
| День недели | Asia/Almaty (`lib/qr-menu.ts`) |
| Файлы dropbox | `menu-azure-1` … `menu-azure-5` (JPG/PNG) |
| Админка | вкладка QR → `AdminQrMenuTab.tsx` |
| Афиша | тот же `banner-azure` из Настроек |

## Важные правки инфраструктуры

- **`lib/api.ts`**: в `getFiles` передаётся `lc` — иначе API отдаёт ~5 файлов и «теряет» меню/баннер.
- **`orders-provider`**: один select меню → данные для баннера и QR сразу.
- **Корзина**: обед и десерт в итоге раздельно (`calculateLunchLineTotal` + десерт).
- **Телефон**: remount после заказа (`phoneInputKey`), чтобы поле снова было редактируемым.
- **`DEV_FORCE_MONDAY_MORNING`**: в PR **`false`** (локальный форс понедельника только для отладки).

## Как прогнать на бою (коротко)

1. Админка → Excel с 8+десерт на неделю.  
2. Админка → QR-меню: JPG Пн–Пт + афиша в Настройках.  
3. `/menu`, `/menu?day=1`, главная: обед + десерт → сумма = обед + 690.  
4. Заказ → повторный ввод телефона ок.
